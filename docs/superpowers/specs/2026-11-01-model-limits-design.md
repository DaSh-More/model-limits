# model-limits: дизайн плагина BB

Дата: 2026-11-01. Статус: на ревью.

## Цель

Видеть в одном месте остатки лимитов и балансы как можно большего числа
провайдеров, на всех устройствах BB, а рядом с футером сайдбара постоянно видеть
модель открытого чата и её остаток.

Первая версия готова, когда:

1. Claude Code и Kimi Code видны на одной странице.
2. Один аккаунт, видимый с двух устройств, занимает одну строку с двумя метками
   устройств. Разные аккаунты занимают разные строки.
3. Баланс DeepSeek виден через пресет HTTP-коннектора.
4. Новый HTTP-сервис, например Polza, добавляется в настройках без релиза.
5. Плашка показывает модель открытого чата и остаток, относящийся к ней.

## Вне первой версии

- История и графики.
- Уведомления о низком остатке.
- Переключение аккаунтов и маршрутизация запросов.
- Запуск кода на устройствах (`bb.host`).
- Конвертация и суммирование валют.
- Внешние команды как источник данных.

## Модель данных

Иерархия: **Провайдер → Аккаунт → Лимит**.

- **Провайдер** — например Claude, Kimi, DeepSeek, Polza.
- **Аккаунт** — личный аккаунт или организация. Уровень скрывается в интерфейсе,
  если у провайдера один аккаунт.
- **Лимит** имеет вид:
  - `window`: процент остатка, название окна, время сброса (может отсутствовать);
  - `balance`: сумма и валюта.
- **Модель** — необязательный признак лимита. У Polza и DeepSeek баланс один на
  весь аккаунт, поэтому обязательным уровнем модель быть не может.
- **Устройство** — не уровень, а метка: где виден аккаунт. HTTP-источники получают
  метку «сервис».

```ts
type Limit =
  | { kind: "window"; id: string; label: string; remainingPercent: number;
      resetsAt: string | null; model: string | null }
  | { kind: "balance"; id: string; label: string; amount: number;
      currency: string; model: string | null };

interface AccountReading {
  sourceId: string;            // "bb" или id HTTP-источника
  providerId: string;
  accountIdentity: string | null; // accountKey, если источник его знает
  accountLabel: string | null;
  planLabel: string | null;
  device: { hostId: string; name: string } | { service: true };
  status: "ok" | "not_installed" | "unauthenticated" | "expired" | "error";
  message: string | null;
  limits: Limit[];
  fetchedAt: string;
}
```

BB отдаёт процент израсходованного (`usedPercent`). Адаптер переводит его в
остаток: `remainingPercent = max(0, 100 - usedPercent)`, поскольку `usedPercent`
может превышать 100.

## Архитектура

Поток: источники → сборщик → единый формат → склейка → снимок → интерфейс.

| Модуль | Назначение | Зависимости |
| --- | --- | --- |
| `sources/bb.ts` | Обходит `bb.sdk.hosts.list()` и вызывает `bb.sdk.system.usageLimits({ hostId, refresh })` для каждой подключённой машины | SDK BB |
| `sources/http.ts` | Запрос, защита, разбор ответа по путям | настройки, секреты |
| `sources/presets.ts` | Описания DeepSeek и Polza | `http.ts` |
| `merge.ts` | Чистая функция: `AccountReading[]` → дерево | нет |
| `thread-match.ts` | Чистая функция: провайдер, модель, устройство чата → лимит | нет |
| `collector.ts` | Таймер, кэш, изоляция сбоев | источники, `bb.storage` |
| `server.ts` | Регистрация настроек, RPC, CLI, сервиса | всё выше |
| `app.tsx` и `components/` | Плашка, страница, секция настроек | RPC плагина |

### Источник BB

Для каждой подключённой машины отдельный запрос `system.usageLimits` с `hostId`.
Набор провайдеров не задаётся в коде: всё, что BB вернул, попадает в список. Это
закрывает Claude и Kimi и автоматически подхватит новых провайдеров.

Статус `not_installed` не показывается. Неподключённая машина не опрашивается: для
неё берутся данные из снимка с меткой «не в сети».

### HTTP-коннектор

Описание источника хранится в `bb.storage.kv`:

```ts
interface HttpSource {
  id: string;
  preset: "deepseek" | "polza" | null;
  providerName: string;
  organization: string | null;
  url: string;
  keySlot: KeySlot;
  authHeader: string;         // по умолчанию "Authorization"
  authPrefix: string;         // по умолчанию "Bearer "
  amountPath: string;
  currencyPath: string | null;
  currencyFixed: string | null; // если валюты нет в ответе
  modelPath: string | null;
  organizationPath: string | null;
  enabled: boolean;
}
```

Пути поддерживают точки и `[*]`, например `balance_infos[*].total_balance`. Если в
пути есть `[*]`, каждый элемент массива становится отдельным балансом. Пути с `[*]`
должны указывать на один и тот же массив, иначе источник считается неверно
настроенным. Сумма принимается как число или строка с числом.

Пресеты:

- **DeepSeek:** `GET https://api.deepseek.com/user/balance`, сумма
  `balance_infos[*].total_balance`, валюта `balance_infos[*].currency`, поле ключа
  `deepseekApiKey`.
- **Polza:** `GET https://polza.ai/api/v2/balance`, сумма `available`, валюта
  фиксированная `RUB`, поле ключа `polzaApiKey`. Показывается `available`, а не
  `amount`: по документации это сумма, которую реально можно потратить с учётом резерва
  и лимитов ключа. Ответ не содержит организацию, поэтому её имя задаётся в настройках,
  а для второй организации заводится отдельный источник со своим ключом.

Защита:

- Только `https:`.
- Редиректы не выполняются.
- Таймаут 10 секунд, ответ до 1 МиБ.
- Ключ отправляется только на адрес своего источника.
- Ключ и тело ответа не пишутся в логи.

Кнопка «Проверить» выполняет запрос на сервере и возвращает разобранный результат
и список путей к полям ответа без значений. Сырое тело ответа в браузер не
передаётся.

### Ключи

Секретные поля SDK объявляются заранее, поэтому их набор фиксирован:
`deepseekApiKey`, `polzaApiKey`, `customKey1` … `customKey5`. Источник хранит только
имя поля. Значения не передаются в браузер. Если поле пусто, источник показывает
«не задан ключ <имя поля>».

### Склейка

- Ключ склейки: `providerId` + `accountIdentity` (`accountKey` от BB).
- Показания с одинаковым ключом образуют один аккаунт; устройства становятся
  метками.
- При расхождении лимитов берётся показание с самым новым `fetchedAt`.
- Показание без `accountIdentity` не склеивается: один аккаунт на устройство. Это
  текущее поведение Kimi, который не отдаёт `accountKey`. У Kimi устройства будут
  отдельными строками с именем устройства в подписи.
- Показание `unauthenticated` или `expired` без идентификатора не может быть отнесено
  к конкретному аккаунту. Оно показывается как подсказка на уровне провайдера: «на
  server-1 не выполнен вход» — если у провайдера есть другие аккаунты, и как
  отдельная строка-статус — если их нет.

### Сборщик

- Сервис с интервалом `refreshSeconds`; значение `0` отключает фоновые запросы.
- Кнопка «Обновить» и CLI запускают сбор вне расписания.
- Источники опрашиваются параллельно, не более 4 одновременно; сбой одного не влияет
  на другие.
- Одновременно идёт только один сбор; повторный запрос дожидается текущего.
- Снимок хранится в `bb.storage.kv` и публикуется через `bb.realtime`.
- При сбое источника сохраняются его прошлые лимиты, с пометкой об ошибке и временем.

## Интерфейс

### Лимит модели в шапке чата

Интерфейс и CLI показывают использованный процент (`100 - remainingPercent`); внутренние расчёты, цвет и минимум по-прежнему считаются по остатку. Элемент шапки двухстрочный: провайдер (модель, только если у неё есть отдельный лимит) и процент с разделителем, ниже лимит и время сброса. Детали всплывают при наведении, на сенсорных экранах по нажатию; нажатие на десктопе открывает страницу лимитов.

Реализуется через `experimental_threadHeaderAction`: элемент в ряду действий шапки чата, не перекрывает интерфейс (перенесено с плавающей плашки после отзыва). Раньше: левый нижний
углу, над футером сайдбара. Пример содержимого: `Fable 5.1 · 72%`.

- Открытый чат определяется через `useBbContext()`.
- Провайдер и устройство берутся из чата (`thread.providerId`,
  `environment.hostId`).
- У записи чата нет поля модели. Модель берётся из последних событий чата
  (`threads.events.list`, поле `data.execution.model` у события с наибольшим `seq`).
- Клик раскрывает карточку с лимитами этого аккаунта и ссылкой на страницу.
- Плашка скрыта на узких экранах и при выключенной настройке `showPill`.
- При смене положения футера в новой версии BB плашка может потребовать подгонки.
  Сбой плашки не затрагивает остальной плагин.

Сопоставление чата с лимитом (`thread-match.ts`), шаги по порядку:

1. Провайдер берётся из чата. Если это Pi, провайдер определяется по имени модели:
   `kimi*` → Kimi, `glm*` → GLM, `claude*` → Claude Code. Иначе — нет данных.
2. Аккаунт — тот, у которого среди устройств есть устройство чата. Для провайдера,
   определённого через имя модели, используется единственный аккаунт провайдера; если
   их несколько, показывается «нет данных».
3. Из окон аккаунта берутся окна без модели и окна, относящиеся к модели чата
   (правило совпадения см. ниже). Показывается наименьший остаток.
4. Если окон нет, а есть баланс, показывается баланс.
5. Если сопоставить не удалось, плашка показывает модель и «нет данных». Чужие цифры
   не показываются.

Без открытого чата минимальный остаток показывается значком на вкладке «Лимиты»
(настройка `pillFallback`: `minimum` или `hidden`).

Цвет индикатора плашки зависит от показанного процента: зелёный выше 30%, жёлтый от
10% до 30% включительно, красный при 10% и ниже. Устаревшие данные и «нет данных»
показываются серым; устаревший процент дополнительно помечается `⚠`. Для чата,
у которого есть только баланс, плашка показывает сумму с валютой и серый индикатор.

Правило совпадения окна с моделью: BB не помечает окна Claude моделью, поэтому окно
считается относящимся к модели, если его название без учёта регистра совпадает с
сегментом идентификатора модели, разделённым дефисами. Например, окно «Fable»
относится к `claude-fable-5-1`. Окно считается окном конкретной модели, только если
название совпадает хотя бы с одной моделью из каталога провайдера
(`bb.sdk.providers`); иначе, как «Current session», оно считается окном всего
аккаунта.

### Страница

Регистрируется как `navPanel`, это основной экран. Сверху показывается время
обновления, кнопка «Обновить» и сводка: минимальный остаток с провайдером, ближайший
сброс, число аккаунтов и число устройств. Ниже — группы по провайдерам,
внутри аккаунты (уровень скрыт, если аккаунт один), внутри лимиты. У каждого аккаунта
метки устройств и подсказки о состоянии. Окна показываются как полоса с процентом и
временем сброса, балансы — суммой с валютой.

### Настройки

Настройки BB (`bb.settings.define`):

| Ключ | Тип | По умолчанию |
| --- | --- | --- |
| `refreshSeconds` | select: 60, 120, 300, 600, 0 | 120 |
| `showPill` | boolean | true |
| `pillFallback` | select: minimum, hidden | minimum |
| `deepseekApiKey`, `polzaApiKey`, `customKey1`…`customKey5` | secret | нет |

Секция `settingsSection` управляет данными из `bb.storage.kv`:

- HTTP-источники: добавить из пресета или с нуля, изменить, проверить, удалить.
- Автоисточники: скрыть провайдера, аккаунт или устройство; задать своё имя аккаунта.

Все значения от браузера проверяются на сервере схемами Zod.

### CLI

`bb model-limits` выводит текущий снимок, `--refresh` запускает сбор, `--json` выводит
ограниченный по объёму JSON без ключей. Команды описаны в скилле плагина
`skills/model-limits/SKILL.md`.

## Поведение при сбоях

| Ситуация | Что показываем | Входит в минимум |
| --- | --- | --- |
| Ошибка источника или таймаут | Последние данные и «обновлено N мин назад» | Да, пока данные не устарели |
| Машина не в сети | Последние данные и «не в сети» | Да, пока данные не устарели |
| Вход не выполнен на устройстве | Подсказка по правилам раздела «Склейка» | Нет |
| Провайдер не установлен на машине | Скрыт для этой машины | Нет |
| Ответ не соответствует путям | Ошибка источника с названием пути | Нет |
| Время сброса окна прошло, новых данных нет | «Данные устарели» | Нет |
| Модель чата не сопоставлена | Модель и «нет данных» | Не применимо |

Данные устаревшие, если старше 30 минут либо если время сброса окна уже прошло.
В минимум входят только окна: баланс нельзя сравнивать с процентом. Неизвестное
значение никогда не показывается как ноль.

## Тестирование

Автотесты на Vitest:

- `merge`: склейка по `accountKey`, Kimi без идентификатора, подсказки о входе,
  выбор самого нового показания.
- `thread-match`: окно модели, окна аккаунта, Pi с `kimi*` и `glm*`, неоднозначный
  аккаунт, отсутствие данных.
- Разбор путей: точки, `[*]`, разные массивы, строковые суммы, отсутствующее поле.
- Защита HTTP: `http:` запрещён, редирект не выполняется, большой ответ, таймаут.
- Статусы устаревания и правила минимума.
- Переход `usedPercent` → `remainingPercent`, включая значения больше 100.
- Сборщик: сбой одного источника не мешает другим и сохраняет прошлые данные.

Живая проверка:

- Установка из git-репозитория на сервер BB.
- Claude с `vps-1` и подсказка о входе на `server-1`.
- `bb model-limits --json` не содержит ключей.
- DeepSeek и Polza — после того как пользователь сам впишет ключи в настройках.
- Внешний вид плашки и страницы проверяет пользователь: агент не видит интерфейс.

## Поставка

- Репозиторий: `https://github.com/DaSh-More/model-limits`, публичный. Секретов в нём
  нет.
- Идентификатор плагина: `model-limits`.
- `dist/` коммитится, чтобы установка из git не требовала сборки.
- Сервер BB находится на `server-1`, разработка идёт на `vps-1`, поэтому основной
  путь установки — `bb plugin install git:https://github.com/DaSh-More/model-limits.git`.
- Плагин рассчитан на установленную версию BB 0.47.1; `engines` задаётся при
  реализации по её версии SDK (`bb plugin types`).
- Экспериментальные API: `experimental_threadHeaderAction`, `experimental_useBadge`. При обновлении BB они могут
  потребовать правки; страница и настройки от неё не зависят.

## Известные ограничения

- Kimi не отдаёт идентификатор аккаунта, поэтому его устройства не склеиваются.
- Pi не отдаёт лимиты через BB; чаты Pi сопоставляются только по имени модели.
- Лимит чата с моделью, у которой нет отдельного окна, определяется по окнам аккаунта.
- На `server-1` не выполнен вход в Claude, пользователь пока не планирует его делать;
  подсказку можно убрать, скрыв устройство для провайдера.
- На `vps-1` не установлен Kimi Code. На `server-1` вход в Kimi выполнен и плагин
  Limits читает его данные, но BB через `system.usageLimits` сообщает
  `unauthenticated`: файл входа называется `kimi-code-env-<хеш>.json`, а плагин Kimi Code
  ищет только `kimi-code.json`.
- Токен Kimi живёт недолго, а плагин его не обновляет. После простоя CLI источник вернёт
  `expired`: прошлые лимиты сохраняются с пометкой и через 30 минут считаются устаревшими.
- Формат ответа Polza взят из документации и не проверен с реальным ключом.
