# Model Limits

Плагин BB: остатки лимитов и балансы провайдеров на всех устройствах BB в одном месте.

## Что делает

- Собирает лимиты, которые BB отдаёт через `system.usageLimits` (Claude Code, Kimi Code и другие), с каждой подключённой машины.
- Показывает балансы HTTP-сервисов (DeepSeek, Polza и любые свои).
- Склеивает один аккаунт, видимый с нескольких устройств, в одну строку с метками устройств.
- Показывает в шапке чата провайдера (или модель, если у неё есть отдельный лимит), использованный процент и строку с лимитом и временем сброса; детали всплывают при наведении.
- Страница «Лимиты»: сводка, группы по провайдерам, окна с процентом и временем сброса, балансы.

## Установка

```
bb plugin install git:https://github.com/DaSh-More/model-limits.git
```

Требуется `bb >=0.47`, `bbPluginSdk >=0.6.79`. Каталог `dist/` лежит в репозитории, сборка при установке не нужна.

## Настройки и ключи

| Ключ | Значения | По умолчанию |
| --- | --- | --- |
| `refreshSeconds` | 60, 120, 300, 600, 0 (0 отключает фоновые запросы) | 120 |
| `showPill` | лимит модели в шапке чата и значок на вкладке | вкл |
| `pillFallback` | значок наибольшего использования на вкладке «Лимиты»: `minimum` или `hidden` | `minimum` |
| `deepseekApiKey`, `polzaApiKey`, `customKey1`...`customKey5` | секретные поля для ключей | пусто |

Изменение `showPill` и `pillFallback` вступает в силу после перезагрузки окна. Именные поля ключей (`deepseekApiKey`, `polzaApiKey`) работают только со своим сервисом.

Значения ключей не передаются в браузер, в логи, CLI и снимок. Источник хранит только имя поля.

## Добавление HTTP-сервиса

В настройках плагина, секция HTTP-источников: добавьте источник из пресета (DeepSeek, Polza) или с нуля. Для своего сервиса укажите:

1. Название провайдера и (необязательно) организацию.
2. `https:`-адрес и поле ключа (`customKey1`...`customKey5`).
3. Заголовок и префикс (по умолчанию `Authorization` и `Bearer `).
4. Путь к сумме (`amountPath`), например `balance_infos[*].total_balance`; валюту: путь в ответе или фиксированную.

Пути поддерживают точки и `[*]`; все пути с `[*]` должны указывать на один массив. Кнопка «Проверить» выполняет запрос на сервере и показывает разобранный результат и пути полей без значений.

Защита: только `https:`, редиректы не выполняются, таймаут 10 секунд, ответ до 1 МиБ.

## CLI

```
bb model-limits              # текущий снимок
bb model-limits --refresh    # собрать данные вне расписания
bb model-limits --json       # ограниченный JSON без ключей
```

## Известные ограничения

- Kimi не отдаёт идентификатор аккаунта, поэтому его устройства не склеиваются.
- Pi не отдаёт лимиты через BB; чаты Pi сопоставляются только по имени модели.
- Лимит чата с моделью без отдельного окна определяется по окнам аккаунта.
- Если на устройстве не выполнен вход, показывается подсказка; её можно убрать, скрыв устройство для провайдера.
- Файл входа Kimi называется `kimi-code-env-<hash>.json`, а Kimi Code ищет только `kimi-code.json`, поэтому BB сообщает `unauthenticated`. Обходной путь: в папке `~/.kimi-code/credentials/` выполнить `ln -s <этот файл> ~/.kimi-code/credentials/kimi-code.json`.
- Токен Kimi живёт недолго и не обновляется плагином. После простоя источник вернёт `expired`: прошлые лимиты сохраняются с пометкой и через 30 минут считаются устаревшими.
- Формат ответа Polza взят из документации и не проверен с реальным ключом.
- Показ в шапке чата использует экспериментальный `experimental_threadHeaderAction`; при обновлении BB её положение может потребовать правки (`src/pill-position.ts`).
